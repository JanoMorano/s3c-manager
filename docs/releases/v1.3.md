# V1.3 Release Notes

S3C Manager v1.3.0 is an architecture and data-model release: the service catalogue gets one canonical column per concept, the schema is applied by a migration runner with a generated baseline, graphs are rebuilt on one shared canvas, the largest source files are split, and the service detail and editor are fully localized.

Detailed changes: see [CHANGELOG.md](../../CHANGELOG.md), section `[1.3.0]`.

## Highlights

- **Schema runner and baseline.** Schema files run once (checksum ledger in `platform.schema_file_ledger`); fresh installs restore `backend/db/postgres/baseline/baseline.sql` (deterministic, built by `scripts/build-schema-baseline.sh`). Schema version 3.9.0.
- **Simpler service data model.** Canonical lifecycle stage, review date, portfolio and service-level SLA (migrations 35–37, 39); import provenance moved to `service_catalog_source` and description fields merged (40): `service_catalog` goes from 70 to 44 columns. The API still returns and accepts the previous field names, except `next_review_due_at` (use `review_due_at`) and the merged description fields.
- **C3 links in one table.** The seven C3 link tables are `c3_entity_link` (42); the old names remain as updatable views.
- **Graphs.** Colour-blind-safe relation encoding, dependency layout, path highlighting, legend, shared `GraphCanvas`, theme-aware minimap, server-side filters and per-view saved node positions (41).
- **Service editor.** Tabs, lifecycle stage select, offering request fields inherited from the service; code split into hooks and panels.
- **Localization.** Service detail, editor and service graph use Czech/English message keys.
- **Quality.** Fresh-install fixes (C3 board state, readiness texts), frontend unit tests (Vitest) in CI, lint clean, invalid CSS colours fixed.

## Upgrade

Run the new image against the existing database: the init runner applies migrations 33–42 once. Back up the database first (see [Upgrade Guide](../upgrade.md)). Custom integrations reading `next_review_due_at`, `value_proposition`, `business_purpose` or `business_summary` from the service API need to switch to `review_due_at`, `consumer_value` and `summary`.
